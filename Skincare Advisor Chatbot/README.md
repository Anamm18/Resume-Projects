## Overview

Skincare Ingredient Advisor answers questions about skincare concerns, skin types, and ingredients by retrieving the closest matches from a vector database and asking a language model to recommend strictly from that retrieved data — never from its own general knowledge. Ask it something outside skincare and it declines instead of guessing. This was built as a portfolio project to demonstrate a complete retrieval-augmented generation (RAG) pipeline: data cleaning, local embeddings, vector search, and grounded generation, wired up behind a chat UI.

## Features

- 🔍 **Semantic retrieval** — questions are embedded locally and matched against ingredient data by cosine similarity, no keyword matching required
- 🚫 **Off-topic guardrail** — a similarity threshold gate blocks unrelated questions before any LLM call is made, backed by a system-prompt guardrail as a second layer
- 🧬 **Skin-type filtering** — mentioning a skin type (oily, dry, combination, sensitive, normal, mature, acne-prone) narrows results to ingredients suited for it
- 📋 **Structured answers** — every response is split into Top Ingredients, Sunscreen Follow-up, and What to Avoid, with every claim cited to a specific ingredient
- 🧹 **Deduplicated results** — retrieval collapses duplicate rows per ingredient so one heavily-listed ingredient can't crowd out the rest of a recommendation
- 📊 **Transparent matching** — an expandable panel shows exactly which ingredients were matched and their similarity scores
- 💬 **Persistent chat history** within a session, with a one-click reset

## How It Works

1. **Embed** — the user's message is embedded locally with `all-MiniLM-L6-v2` (sentence-transformers), no API call required for this step
2. **Retrieve** — the embedding is compared against a persistent ChromaDB collection of ingredient embeddings; results below a similarity threshold are treated as off-topic and refused immediately
3. **Deduplicate & filter** — duplicate ingredient rows are collapsed to one per ingredient, then narrowed by skin type if one was mentioned in the question
4. **Generate** — the filtered ingredient data is sent to Groq (`openai/gpt-oss-20b`) with a system prompt that requires the model to answer only from that data, in a fixed three-part structure

## Dataset

2,100 skincare ingredient records covering categories such as peptides, botanicals, and brightening agents, with fields for primary function, key benefits, how to apply, recommended frequency, sunscreen follow-up, suitable skin types, combination warnings, comedogenic rating, pregnancy safety, and price tier. Rows missing concentration or pH range data were dropped during cleaning. The dataset carries one row per ingredient/product-format pair, so retrieval deduplicates by ingredient name before results reach the model.

## Project Structure

```
Skincare-ChatBot/
├── Skincare_ChatBot.ipynb     # data cleaning, embedding generation, pipeline prototyping
├── app.py                     # Streamlit app — retrieval, generation, and UI
├── ingredient_data.pkl        # cleaned ingredient dataframe (generated by the notebook)
├── chroma_skincare_db/        # persistent Chroma vector store (generated by the notebook)
├── .env.example                # template for required environment variables
└── README.md
```

`app.py` currently holds configuration, retrieval, generation, and the UI together in one file. Splitting it into separate `config.py`, `build_index.py`, `retrieval.py`, and `chatbot.py` modules is a planned refactor, not the current state.

## Getting Started

### Prerequisites

- Python 3.12
- [uv](https://docs.astral.sh/uv/) for dependency management
- A [Groq API key](https://console.groq.com/keys)

### Installation

```bash
git clone <your-repo-url>
cd Skincare-ChatBot
uv sync
```

### Configuration

```bash
cp .env.example .env
```

Then open `.env` and set:

```
GROQ_API_KEY=your-groq-api-key-here
```

### Build the data artifacts

Run `Skincare_ChatBot.ipynb` once end-to-end. This generates `ingredient_data.pkl` and populates `chroma_skincare_db/`, both of which `app.py` expects to find at startup.

### Run the app

```bash
uv run streamlit run app.py
```

The app opens at `http://localhost:8501`.

## Usage

Type a skincare question into the chat box, for example:

- `What ingredients help with oily, acne-prone skin?`
- `Is salicylic acid good for oily skin?`
- `What should I avoid combining with retinol?`

Questions unrelated to skincare (`who is Sachin Tendulkar`) are declined rather than answered.

## Known Limitations

- Only knows what's in the ingredient dataset — no awareness of specific commercial products or brands
- The off-topic guardrail is a similarity threshold, not true topic classification, so edge cases can occasionally slip through or be refused incorrectly
- Generation requires a live connection to Groq; without it, the app still shows matched ingredients but can't produce a full answer
